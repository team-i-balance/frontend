# AI 누리 보안 · PC 앱 (KP Guard 프로토타입)

생성형 AI에 프롬프트를 보내기 전에 개인정보·기밀정보를 찾아 가려 주는 도구. 탐지·가명화·기록·답변 복원은
**팀 서버(backend)**가 하고, 이 PC의 앱은 감시·화면·조직 베이스 확인을 맡는다. 서버로 보내지 않는 "이 PC에서만 처리" 모드도 있다.

> **지금 범위 (시연용):** Windows에서 **브라우저의 Claude(claude.ai, Claude Code 웹 `claude.ai/code` 포함)·Codex(`chatgpt.com/codex`)**와
> **터미널의 Claude Code·Codex CLI 프롬프트**(Windows Terminal·콘솔)를 실시간으로 감시하고, 모두 같은 칩 화면을 쓴다.
> ChatGPT 대화 페이지는 감시하지 않고, macOS는 검증하지 않는다 (코드는 있다).
> UI는 이후 교체한다. 작업 목록: `.kiro/specs/kp-guard/tasks.md`

## 실행

```powershell
pip install -r requirements.txt     # 선택: 트레이 아이콘, 파일 검사, 소형 모델 실행 모듈 (없으면 그 기능만 꺼짐)
python -m agent.main                 # 설정 창과 함께 시작
pythonw kp_guard.pyw --background    # 창 없이 트레이에 상주 (자동 시작이 쓰는 방식)
```

첫 실행 때 "Windows 로그인 시 자동 실행" 여부를 묻는다. 설정 창에서 언제든 켜고 끌 수 있다
(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\KPGuard`, 관리자 권한 불필요).

## AI 입력창에 자동 하이라이트 (브라우저 Claude·Codex, 터미널 CLI)

KP Guard를 실행하고 평소처럼 Chrome이나 Edge에서 Claude(claude.ai, Claude Code 웹)나 Codex(chatgpt.com/codex)에,
또는 터미널에서 Claude Code·Codex CLI에 입력합니다. 기본으로 켜진
**AI 입력창에 자동 하이라이트**가 현재 문장을 팀 서버(`POST /process/preview`)에서 검사하고, Windows UI Automation이 알려 준
단어 좌표에 반투명 표시를 그립니다. 확장 설치나 연결 코드는 필요하지 않습니다.

화면 이름은 **AI 누리 보안**입니다 (실행 파일·설정 폴더·환경 변수는 그대로 `KPGuard`·`KPGUARD_*`).

### 칩 (새 창 없이 칩을 펼쳐 마무리)

칩은 단계형입니다. 선택지는 세로로 놓이고, 하위 선택지가 있는 칩을 고르면 오른쪽에 다음 칩이 열리며 앞 칩은 고른 칸이 파랗게 표시된 채 남습니다.
첫 칩은 입력창 바깥(위, 자리가 없으면 아래)에 떠서 프롬프트를 가리지 않고, 단어와 칩·고른 칸과 다음 칩은 ERD처럼 파란 점선으로 이어집니다.
최종 선택(적용·사유)을 하면 칩이 모두 사라진 뒤 실행되고, 결과 한 줄과 **다음 항목 · 되돌리기** 칩이 잠깐 뜹니다.
호버·누르기·선택·열기·닫기에 애니메이션이 있습니다.

설정에서 직접 켠 기능(복사한 프롬프트 자동 점검 등)이 아니면, 하이라이트에서 시작한 행동은 창을 열지 않고 칩 안에서 끝납니다.

1. 하이라이트(옅은 파란 면 + 파란 밑줄)를 누르면 칩 두 개가 열립니다: **마스킹 · 원문유지**
2. **마스킹** → 위에는 바뀔 값만 보입니다(예: `[전화번호_1]`, 지우는 값은 취소선). 아래 칩에서 **적용**(같은 값이 여러 곳이면 모두) 또는 **모두 적용 N**(하이라이트 전부)을 고릅니다
3. **원문유지** → 사유 칩 셋: **업무상 필요 · 오탐 · 승인된 개인정보**. 오탐은 앱을 끌 때까지 다시 탐지하지 않습니다. 비밀값·기밀은 원문유지를 고를 수 없습니다
4. 적용하면 원래 입력창에서 **그 자리만, 입력하듯이** 바뀝니다 (입력창 전체를 바꾸거나 점검 창을 열지 않음). 끝나면 칩에 결과 한 줄과 **다음 항목 · 되돌리기**가 남습니다
5. **하이라이트가 남아 있으면 그 입력창의 Enter(전송)를 막고** 첫 항목의 칩을 엽니다. Ctrl(⌘)+Enter로 보내는 입력창도 있어 함께 막습니다. Shift+Enter 줄바꿈과 다른 곳(주소창 등)의 Enter는 그대로입니다
6. 남은 하이라이트가 없어지면 이 입력의 결정을 서버(`/process/decide`)와 이 PC 로그에 한 번 기록합니다. 마스킹한 입력은 답변 복원 창(`Ctrl+Alt+R`)에서 10분 안에 한 번 복원할 수 있습니다

같은 페이지의 빈 곳을 클릭하면 칩만 닫힙니다. 입력창 수정·스크롤 시 현재 위치로 표시를 갱신합니다.

- Windows: 칩 창은 포커스를 가져가지 않습니다(`WS_EX_NOACTIVATE`). 바꿀 때는 UI Automation으로 그 범위를 고르고 유니코드 키 입력으로 칩니다. Enter는 저수준 키보드 훅으로, 하이라이트가 남은 그 입력창에 커서가 있을 때만 막습니다 (주소창 등 다른 곳의 Enter는 그대로)
- macOS: 손쉬운 사용으로 범위를 고르고 `AXSelectedText`로 바꿉니다(안 되면 키 입력). Enter는 이벤트 탭으로 막으며 같은 손쉬운 사용 권한을 씁니다
- 바꾼 뒤에는 입력창을 다시 읽어 결과가 맞는지 확인하고, 다르면 칩에 실패를 알리고 기록 상태를 되돌립니다

- 감시하는 곳은 claude.ai·chatgpt.com/codex 페이지의 작성란과 터미널 CLI의 지금 프롬프트뿐입니다. ChatGPT 대화·다른 사이트의 입력과
  터미널의 이전 출력(스크롤백)은 읽지도 서버로 보내지도 않습니다
- 결정 기록의 대상 AI(`target_ai`)는 입력한 곳을 따릅니다: `Claude (claude.ai)` · `Codex (chatgpt.com/codex)` · `Claude Code (CLI)` · `Codex (CLI)`
- 입력 중 검사로는 작업·로그를 만들지 않고, 사용자가 가명화·원문 사용 등을 고르면 기존 처리 API를 씁니다
- **이 PC에서만 처리**와 감시 일시정지도 자동 하이라이트에 적용됩니다

### 터미널의 Claude Code·Codex CLI

Windows Terminal과 콘솔(macOS는 터미널·iTerm2)에서 Claude Code(`❯`)·Codex(`›`) CLI의 **지금 쓰고 있는 프롬프트 칸만** 읽습니다.
CLI 머리글·바닥글(`? for shortcuts`, 남은 컨텍스트 등)로 알아보며, 이전 대화·명령 출력과 일반 셸 입력은 읽지 않습니다.
하이라이트·칩·Enter 막기는 브라우저와 같고, 첫 칩은 프롬프트 칸 위(자리가 없으면 아래)에 뜹니다.

- **적용(그 자리 바꾸기):** 터미널 프롬프트는 손쉬운 사용으로 커서를 옮길 수 없어서, 사람이 고치듯 입력합니다.
  커서 위치를 표시 문자(`¤`) 하나로 확인해 바로 지운 다음, 마지막 줄을 바꿀 값 앞까지 Backspace로 지우고 나머지를 다시 칩니다.
  뒤에 친 공백은 그대로 둡니다. **커서가 입력 끝에 있고 값이 마지막 줄에 있을 때만** 바꾸고, 아니면 아무것도 바꾸지 않고 칩에 알립니다
- 콘솔(conhost)에서는 하이라이트가 클릭을 직접 받습니다. 콘솔에 클릭이 가면 빠른 편집 선택 모드가 되어 CLI가 멈추기 때문입니다

**선택 기능 · 브라우저 확장.** UI Automation 대신 확장으로 claude.ai 작성란을 직접 다루려면 설정 창의
**브라우저 연결 코드 복사**를 누르고 확장에 붙여넣습니다. [확장 연결 및 칩 사용법](browser-extension/README.md)
확장은 claude.ai만 다룹니다. Codex 웹과 CLI에는 확장 없이 위의 PC 앱 칩 화면이 그대로 뜹니다.

## 처리 위치: 서버 (기본) / 이 PC

설정 창의 "처리 위치"에서 고른다. 기본은 서버이고 주소는 `https://13.193.207.69`(팀 backend, Caddy HTTPS)이다.
주소는 설정 창이나 `KPGUARD_SERVER_URL` 환경 변수로 바꾼다. 예전 기본 주소(`http://13.193.207.69:8501`)를 그대로 쓰던 설정은
새 주소로 옮긴다 (서버가 이제 uvicorn을 127.0.0.1에만 연다).

| 하는 일 | 서버 처리 | 이 PC에서만 처리 |
|---|---|---|
| 개인정보 탐지·가명화 (`[이름_1]` 같은 자리표시) | 서버 `POST /process` | 이 PC 엔진 (가짜 값으로 바꿈) |
| 사용자 선택 기록 (변환문 전송·원문 전송·취소, 사유) | 서버 `POST /process/decide` | 이 PC 로그만 |
| AI 답변 복원 | 서버 `POST /process/restore` | 이 PC 매핑 |
| 조직 베이스(코드네임·고객사·사내 도메인) | **서버로 보내기 전에 이 PC에서 태그로 바꿈** | 이 PC |
| 기밀 표기·사내 소스코드 차단 | 이 PC (서버 SLM 기밀 탐지와 함께 쓰는 안전망) | 이 PC |
| 복사한 글을 창에 띄울지 판단 | 이 PC 규칙·사전 (복사한 모든 글을 서버로 보내지 않기 위해) | 이 PC |
| 파일 검사 (엑셀 보호본) | 서버 `POST /files/sanitize` → `GET /files/{work_id}/download` (조직 베이스·기밀 표기는 이 PC에서 먼저) | 이 PC |

서버 처리 점검 창은 서버 결과를 원문과 맞춰 하이라이트하고, 항목별 되돌리기·놓친 정보 신고를 보낼 글에 반영한다.
서버가 위치를 돌려주지 않으므로 원문 위치는 앱이 맞춰 찾는다. 위치가 하나로 정해지지 않는 항목은 되돌리기를 막는다.

- **서버 작업은 `/process` 시점부터 10분 동안만 남고, 답변 복원은 한 번만 된다** (backend `app/sessions.py`)
- 서버 `/health`가 알려 주는 탐지 범위(모델+규칙 / 규칙만, 기밀 탐지 SLM 준비 여부, backend#11)를 설정 창에 보여 준다.
  규칙만인 서버에는 처음부터 규칙만 모드로 보내고(글을 두 번 보내지 않음) "이름·주소 미검사"라고 표시하며, 파일은 보내지 않는다.
  탐지 범위를 알려 주지 않는 이전 서버는 400(`LOCAL_PII_MODEL_DIR`)을 받은 뒤 규칙만 모드로 다시 요청한다
- 서버에 닿지 않으면 점검 창에서 "이 PC에서 검사"로 같은 글을 이 PC 엔진으로 검사할 수 있다

### 서버 연결 보안: 토큰·인증서 (backend#10)

팀 서버는 HTTPS(Caddy)로만 열려 있고, `/health`·`/auth/dev-token` 말고는 `Authorization: Bearer <토큰>`을 요구한다.
설정 창 "처리 위치"의 **인증·인증서…**에서 정한다 (`agent/gui/server_auth.py`).

| 토큰 | 쓰는 법 |
|---|---|
| 개발용 토큰 (기본) | 서버 `POST /auth/dev-token`이 바로 내주는 토큰을 받아 쓴다. 서버 메모리에만 있어 서버를 다시 시작하면(배포마다) 무효가 되므로, 401이면 한 번 새로 받아 다시 보낸다. 운영 서버가 막으면(`DISABLE_DEV_TOKEN=1`, 403) 팀 토큰을 넣으라고 안내한다 |
| 팀 토큰 | 관리자에게 받은 토큰(서버 `API_TOKENS`). 설정 창에 넣으면 사용자 폴더의 `KPGuard/settings.json`에 저장한다 (Windows `%LOCALAPPDATA%`, macOS `~/Library/Application Support`. DPAPI 보호는 태스크 24) |

- 토큰은 HTTPS나 이 PC 안의 서버(127.0.0.1)로만 보낸다. 다른 PC의 HTTP 주소에는 보내지 않고 멈춘다
- 연결 확인("저장·연결 확인")은 `/health`와 api 권한으로 읽기만 하는 `GET /policy/current`로 토큰까지 확인한다. 글은 보내지 않는다

**인증서 지문 고정.** 서버는 도메인 없이 IP 주소에 자체 서명 인증서를 쓴다. 시스템이 믿는 인증서가 아니므로 처음 연결하면
"인증서 확인 필요"가 뜬다. 인증·인증서 창이 서버가 보낸 인증서의 SHA-256 지문을 보여 주면, **서버 관리자에게 받은 지문과
같은지 확인한 뒤** 신뢰한다 (붙여넣으면 바로 비교한다). 서버에서 지문 확인:

```bash
openssl x509 -in /etc/caddy/selfsigned/cert.pem -noout -fingerprint -sha256
```

- 지문은 서버(호스트:포트)별로 저장한다. 고정한 뒤에는 연결할 때마다 요청을 보내기 전에 서버 인증서가 그 지문과 같은지 보고,
  다르면 토큰·글을 하나도 보내지 않고 끊는다 ("인증서가 신뢰한 것과 달라요" — 가로채기이거나 서버 인증서를 바꾼 경우)
- 회사 프록시(`HTTPS_PROXY`)를 써도 서버와 직접 TLS를 맺으므로 지문 확인은 그대로다. TLS를 풀어 보는 프록시면 지문이 달라 막힌다
- 지문을 고정하지 않은 https 주소는 시스템 인증서 저장소로 확인한다 (공인 인증서로 바꾼 뒤에는 고정을 해제해도 된다)
- 배포 관리(MDM): `KPGUARD_SERVER_URL`, `KPGUARD_API_TOKEN`(팀 토큰), `KPGUARD_SERVER_PIN`(지문)으로 미리 넣을 수 있다

연결 오류 종류 (`ServerError.kind`, 화면 안내와 파일 검사 사유가 이것을 따른다):
`unreachable`(닿지 않음) · `tls`(TLS 실패) · `untrusted_cert`(인증서 확인 필요) · `pin_mismatch`(인증서가 다름) ·
`insecure`(HTTP로 토큰을 보내지 않음) · `unauthorized`(401) · `forbidden`(403) · `no_model` · `expired` · `failed` · `rejected` · `bad_response`.
인증서·토큰 문제면 점검 창에 "설정 열기"가 나오고, 서버가 처리하지 않은 게 분명한 오류면 답변 복원을 다시 시도할 수 있다.

## 탐지 단계 (이 PC에서 처리할 때)

| 단계 | 내용 | 켜지는 조건 |
|---|---|---|
| 0 규칙 | 주민·카드·계좌·전화·이메일·IP·API 키 (검증식·문맥 점수) | 항상 |
| 1 사전·베이스 | 이름(성씨+호칭)·나이·주소·학교, 조직 베이스(코드네임·고객사·내부 도메인), 기밀 표기·사내 소스코드 | 항상 |
| 2 소형 모델 | AEGIS ONNX 개인정보 모델 (팀 backend `local_ai`): 이름·주소·생년월일·신분증 번호·계정 등 | 모델 폴더를 지정했을 때 |
| 2 SLM | 미세조정 GLiNER (팀 `slm` 레포): 회사 기밀 구간·코드네임 | 모델 파일을 받은 뒤 ONNX로 변환해 연결 예정 |

**소형 모델(AEGIS) 켜기.** 모델 파일은 레포와 exe에 들어 있지 않다. 아래 파일이 든 폴더를
설정 창의 "모델 폴더 선택…"으로 지정하거나 `%LOCALAPPDATA%\KPGuard\models\aegis`에 넣으면 다음 실행부터 켜진다.

```
model.onnx (또는 model_quantized.onnx, onnx/model_quantized.onnx)
tokenizer.json
config.json   (id2label)
```

- 모델은 백그라운드에서 불러오고, 준비되기 전에는 규칙·사전만으로 검사한다. 점검 창 오른쪽 위에 검사 범위가 나온다.
- 모델 추론이 실패하면 그 글은 "규칙·사전만"으로 표시하고 경고한다. 파일 검사는 보호본을 만들지 않는다.
- 확률이 0.6 미만인 모델 결과는 바로 바꾸지 않고 밑줄(확인 필요)로 보여 준다.
- 이름·주소 끝에 모델이 함께 잡은 조사("김민수의")는 팀 서버와 같은 규칙으로 뗀다(backend#12). 덜 떼는 쪽이라
  세 글자 이름 뒤 '이'·'가'("김민준이")는 이름 끝 글자일 수 있어 그대로 둔다.
- onnxruntime은 CPU로 실행하고 실행 중에 모델을 내려받지 않는다. 토크나이저도 폴더의 `tokenizer.json`만 읽는다.
  onnxruntime(1.31.1에서 확인)은 `disable_telemetry_events()`를 불러도 추론 중 `mobile.events.data.microsoft.com`으로
  연결을 시도해서, 앱은 진입점(`agent/main.py`)과 모델 모듈에서 onnxruntime을 불러오기 전에 `ORT_DISABLE_TELEMETRY=1`을 넣는다
  (backend#13과 같은 방식). 90초 동안 추론해 연결 시도 0회를 확인했고, 새 인터프리터에서 값을 확인하는 테스트가 있다.

## 파일 검사 (엑셀 보호본)

`Ctrl+Alt+F`, 트레이 메뉴, 설정 창에서 연다. `.xlsx`를 고르면 팀 backend `file_sanitizer`로 표를 읽고,
칸마다 점검 창과 같은 엔진으로 가린 **보호본**을 만든다. 원본 파일은 바꾸지 않는다.

- 숨긴 시트·행·열, 메모, 문서 속성, 파일 이름, 숫자 서식 문구까지 검사한다. 보호본에는 보이는 값만 남는다
- "홍길동 학생" 칸에서 이름으로 확인한 값은 문맥이 없는 다른 칸의 "홍길동"도 함께 가린다
- 프롬프트와 같은 매핑을 써서 AI 답변의 가짜 값을 답변 복원 창에서 되돌릴 수 있다
- 기밀 표기가 있으면 파일 전체를 차단한다. 보호본을 다시 읽어 가린 값이 남았으면 보호본을 내놓지 않는다
- 수식·매크로·차트·병합 셀·필터 등은 아직 지원하지 않는다 (값만 남긴 표로 저장해서 다시 검사)
- 로그에는 유형·건수만 남는다

**서버 처리일 때** (업로드 → 결과 → 보호본 받기, `agent/files/remote.py`)

1. 이 PC: 숨긴 시트·행·열, 메모, 문서 속성을 빼고 조직 베이스를 태그(`[프로젝트A]` 등)로 바꾼 사본을 만든다.
   기밀 표기·사내 소스코드가 있으면 여기서 막고 서버로 보내지 않는다. 원래 파일 이름 대신 `upload.xlsx`로 올린다
2. 서버(`POST /files/sanitize`): 개인정보를 `[이름_1]` 같은 자리표시로 바꾼 보호본을 만든다. 다른 파일을 처리 중이면(429) 잠시 기다렸다 다시 보낸다
3. 이 PC: 보호본을 바로 받는다(`GET /files/{work_id}/download`, 서버는 한 번만 내준다). 메모리에만 두고 "보호본 저장"으로 쓴다.
   서버 응답에는 무엇을 가렸는지가 없어서, 올린 사본과 받은 보호본을 칸끼리 맞춰 유형·개수를 센다.
   올린 사본에 없던 칸·숨은 내용, 이 PC에서 가린 값·기밀 표기가 보호본에 있으면 쓰지 않는다
4. 서버에 모델이 없거나(503) 닿지 않으면 "이 PC에서 검사"로 같은 파일을 이 PC 엔진으로 검사할 수 있다

- 파일의 서버 자리표시는 아직 답변 복원이 안 된다 (서버에 파일 복원 API가 없다, backend#29). 조직 베이스 태그는 이 PC에서 복원된다
- 프롬프트와 파일은 서버에서 자리표시 번호를 따로 매긴다. 프롬프트 복원에서 최근 1시간 안에 받은 파일 보호본과
  같은 자리표시를 바꾸면 "확인이 필요해요"로 알린다 (파일 쪽 값이었다면 틀린 값이다)
- 서버 파일 API는 기록을 남기지 않으므로 파일 검사 기록은 이 PC 로그에 남긴다 (backend#32)

## 데스크톱 앱 빌드

백그라운드에 상주하면서 프롬프트를 PC 안에서만 처리하고 기업 PC에 설치해 쓰는 도구라서, 웹 배포 없이 Windows 데스크톱 앱으로 배포한다.

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

결과물은 `dist\KPGuard\` 폴더이고 `KPGuard.exe`로 실행한다 (트레이 상주는 `KPGuard.exe --background`).
배포할 때는 폴더째 복사한다. 자동 시작은 exe의 현재 경로를 등록하므로, 폴더를 옮기면 설정 창에서 자동 시작을 껐다 다시 켠다.
exe에는 onnxruntime 등 실행 모듈만 들어가고 모델 파일은 들어가지 않는다 (위의 "소형 모델 켜기" 참고).

## 화면 디자인

기본 디자인 설정은 [`docs/DESIGN-SETTINGS.md`](docs/DESIGN-SETTINGS.md)(AI 누리 보안 — 보안팀 콘솔과 같은 설정)이다.

- **시그널 블루는 세 곳에만**: 창마다 주 행동 하나(`#3570E0` 채운 버튼), 고른 것(옅은 파란 면), 키보드 포커스(`#8FB5FF`).

- 글자는 값·문장 `#F1F3F5`, 메타·라벨 `#A3ABB4` 두 단계. 크기 12·13·14·15·16·18·20·22·28, 굵기 400·500·600만
- 상태색(빨강 `#FF7272`·초록 `#55DC92`·노랑 `#F8C952`)은 아이콘·원문 표시에만, 넓은 면은 같은 색 12% 옅은 면.

- 알림(토스트)은 화면 위 가운데, 패널 면에 상태색 테두리·아이콘 (완료·경고·오류)
- 칩은 패널 면 + 선, 모서리 12. 고르는 칩(마스킹·원문유지·사유)은 모두 같은 알약 모양이라 색으로 답을 암시하지 않는다
- 가린 값 표시: 잡힌 값 옅은 파란 바탕, 변환된 값 회색 바탕, 원문 그대로 나가는 값 옅은 빨강 + 빨강 글자, 지운 값 취소선.
  표·툴팁의 원문 값은 일부만 보여 준다 (`홍*동`, `01*-****-**78`)
- 버튼 높이 큰 48 · 기본 40 · 작은 32 · 표 안 28, 모서리 12(작은 버튼 6). 입력 40, 토글 36×22, 체크박스 18
- 로고 마크 '문장과 가림'(`agent/assets/brand/*.svg`)을 창 아이콘과 설정 창 머리에 쓴다
- 글꼴은 Pretendard를 앱에 넣어 두었다(`agent/assets/fonts`, SIL OFL 1.1, `Pretendard-LICENSE.txt`).
  Windows에서 이 프로세스에만 등록해 쓰고, 없으면 맑은 고딕으로 바뀐다. 확장은 설치된 Pretendard가 있으면 쓴다
- tkinter에 없는 것: 자간, 숫자 폭 고정(tabular-nums), 그림자, 반투명. 옅은 면은 바탕색에 미리 섞었고,

  크기는 화면 배율(DPI)에 맞춰 키운다

## 흐름

1. 백그라운드 상주 (트레이 아이콘: 초록=감시 중, 주황=일시정지, 회색=꺼짐)
2. 트리거
   - 기본: 브라우저 Claude(claude.ai, Claude Code 웹 포함)·Codex(chatgpt.com/codex) 입력창이나 터미널의 Claude Code·Codex CLI
     프롬프트에 쓰는 동안 자동 하이라이트 → 칩(위 "칩" 참고)
   - 설정에서 **복사한 프롬프트 자동 점검**을 직접 켜면: 프롬프트를 **복사**할 때 민감정보가 있으면 점검 창이 뜬다
     (기본은 꺼짐. 켜 두면 AI 답변을 복사할 때 답변 복원 창도 뜬다)
   - `Ctrl+Alt+P`: 빈 점검 창을 열고 프롬프트를 직접 작성
   - `Ctrl+Alt+F`: 엑셀 파일 검사 (보호본 만들기)
3. 점검 창: 왼쪽 원문(수정 가능) / 오른쪽 변환문, 유형별 하이라이트
4. **하이라이트(또는 표의 행) 클릭 → 입력창과 같은 칩**
   - 마스킹 → 바뀔 값만 보이고 적용. 이 PC 처리에서는 방식(대체·일반화·삭제·태그) 칩으로 바뀔 값을 미리 본다
   - 원문유지 → 업무상 필요 / 오탐 / 승인된 개인정보 (오탐은 앞으로 탐지하지 않음)
   - 기밀: 마스킹 = 이 부분 빼고 보내기, 원문유지 = 사유를 남기고 차단 해제
   - 밑줄 항목 = 확인 필요(자동 변환 안 함), 칩에서 마스킹을 고른다
5. 놓친 정보: 원문에서 드래그 → 우클릭 → "이것도 가려줘"
6. **[변환문 복사]** → Claude 입력창에 붙여넣기 / [취소] / [원문 그대로 사용] → 버튼 위에 사유 칩 셋
7. `Ctrl+Alt+R`로 답변 복원 창을 연다 (자동 점검을 켰다면 AI 답변을 복사할 때 자동으로 뜬다)
8. 행동은 큐로 분류돼 로그에 남는다 (원문 없음): `%LOCALAPPDATA%\KPGuard\events.db`, `logs\YYYY-MM-DD.jsonl`

트레이 메뉴의 "예시로 점검해보기"에서 상담 안내문·코드네임·API 키·사내 소스코드·공개 질문 예시를 바로 열 수 있다.

## 프로토타입 한계

- 기본 탐지는 정규식 + 작은 사전. 소형 모델(AEGIS)은 모델 파일을 지정해야 켜지고, 실제 모델로는 아직 측정하지 않았다
  (CPU 실행만, INT8 변환·NPU는 Phase 4). SLM(기밀 구간)은 모델 파일을 받은 뒤 연결한다
- 파일 검사는 값만 있는 `.xlsx`만 지원한다. docx·pptx·hwp·pdf는 Phase 2 남은 작업
- 실시간 감시는 브라우저의 claude.ai·chatgpt.com/codex(Windows Chrome·Edge)와 터미널의 Claude Code·Codex CLI만 한다.
  검증은 재현 페이지·재현 CLI 프롬프트와 가짜 서버로 했고, 로그인한 실제 claude.ai·Codex와 실제 CLI는 사람이 확인한다.
  Codex 웹의 작성란은 ChatGPT와 같은 구조(`#prompt-textarea`, ProseMirror)로 보고 재현했다
- Enter 막기와 입력창 제자리 바꾸기는 CI에서 확인한다: 브라우저는 `tools/smoke_native.py`(칩 열기까지),
  콘솔 CLI는 `tools/smoke_terminal.py`(Enter 막기 → 마스킹 적용 → 바뀐 프롬프트 전송까지)
- 터미널 CLI의 제자리 바꾸기는 커서가 입력 끝에 있을 때 마지막 줄의 값만 된다. 이모지·결합 문자가 바꿀 자리 뒤에 있으면 하지 않는다
- 이 PC 처리의 매핑은 앱 메모리에만 있어 앱을 끄면 이전 답변은 복원할 수 없다 (의도된 동작).
  서버 처리의 매핑은 서버에 10분, 한 번 복원할 때까지만 있다
- 서버 처리는 실제 팀 서버(`13.193.207.69`)로는 검증하지 못했다 (개발 환경에서 닿지 않음).
  같은 backend 코드(main `2042ae3`)를 로컬에서 띄워 검사·기록·복원·규칙만 모드를 확인했고,
  파일 검사는 main `4882ff0`(PR #17 보호본 다운로드)으로 업로드·한 번 받기·모델 없음(503)을 확인했다.
  토큰·HTTPS는 main `c7e8a48`(backend#10)을 자체 서명 인증서 HTTPS로 띄워 지문 확인·고정, 개발용 토큰 발급·서버 재시작 뒤
  다시 받기, 팀 토큰, 틀린 토큰(401), 발급 막힘(403), 지문 불일치를 확인했다. 팀 서버의 실제 인증서 지문은 서버 관리자에게 받아야 한다
- 모든 예시 값은 합성 데이터
- exe는 코드 서명이 없어 SmartScreen·백신 경고가 뜰 수 있고, 설치 프로그램은 아직 없다 (태스크 27)

## macOS 실행 (검증하지 않음)

> 시연 범위에서 빠져 CI가 macOS를 돌리지 않는다. 아래는 남아 있는 코드의 사용법이다.

macOS에서 Python 3.10 이상과 tkinter가 준비되면 가상환경을 만들고 `pip install -r requirements-dev.txt`를 실행한 다음 `python -m agent.main`으로 실행한다. 모델 파일은 별도로 준비해 설정 창에서 선택한다. 네트워크를 사용하지 않으려면 처리 위치를 **이 PC에서만 처리**로 선택한다. 기존 설정의 서버 주소와 처리 위치도 확인한다.

| 기능 | Windows | macOS |
|---|---|---|
| 수동 텍스트 검사·XLSX | 지원 | 자동 테스트 적용; 실제 GUI 확인 필요 |
| 트레이/메뉴 막대 | Windows 트레이 | 메뉴 막대 구현; 실제 GUI 확인 필요 |
| 전역 단축키 | Ctrl+Alt | ⌘+⌥ 감지; 입력 모니터링 권한과 충돌 확인 필요 |
| 클립보드 감시 | Windows API | macOS Pasteboard; 권한·앱 간 복사 확인 필요 |
| 로그인 자동 실행 | 레지스트리 | LaunchAgent; 실제 로그인 재검증 필요 |
| 터미널 CLI 하이라이트·칩 | Windows Terminal·콘솔 (CI) | 터미널·iTerm2 손쉬운 사용; 실제 GUI 확인 필요 |

macOS의 시스템 설정에서 앱이 요청하는 입력 모니터링 등 권한을 확인한다. 권한을 거부하면 자동 감시나 전역 단축키가 제한될 수 있으며 직접 입력으로 점검할 수 있다. 전역 단축키 입력은 다른 앱에도 전달될 수 있다.

자동 테스트: `python -m unittest discover -s tests -t . -v`. CI는 Windows에서만 실행한다 (macOS는 검증하지 않음). GUI, 실제 모델, 권한 승인 및 로그인 흐름은 자동 테스트만으로 확인되지 않는다. 원문과 매핑을 외부로 전송하지 않는 조건을 적용할 때는 실제 설정과 연결 대상을 별도로 확인한다.

## macOS 앱 빌드

macOS에서 Python 가상환경을 활성화하고 `pip install -r requirements.txt -r requirements-build.txt`를 실행한 뒤 `./build-macos.sh`로 `dist/KPGuard.app`을 만듭니다. 모델 파일은 앱에 포함되지 않으므로 별도로 로컬에 준비해야 합니다.

개발용 빌드는 서명 및 Apple 공증을 자동으로 수행하지 않습니다. 다른 Mac에 배포할 때는 개발자 인증서와 공증을 별도 준비하고 Gatekeeper 동작을 확인해야 합니다. 이 빌드는 실제 배포 환경에서 아직 검증되지 않았습니다.
